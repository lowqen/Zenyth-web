# 라이브러리 — yixindb 파일 관리 계획서 (2026-11-22)

DB 탭을 «라이브러리»로 바꾼다. 폴더(또는 브라우저 저장소) 안의 yixindb 파일을 커버 격자로 늘어놓고, 고르면 바로 그 DB 의
내용을 보고, 이름 · 커버(26주형) · 병합 · 분리를 한다. 웹 · 데스크톱(이 저장소 한 벌)을 먼저, 안드로이드는 같은 형식으로 나중에.

## 0. 결정 (사용자, 2026-11-22)

| 물음 | 결정 |
|---|---|
| «기보»의 뜻 | 앱이 쓰는 **yixindb 국면 DB**. 열람 = DB 안 국면 트리 · 주형 분포를 보고 그 국면을 판에서 연다 |
| 범위 · 순서 | 웹 · 데스크톱 먼저, 안드로이드 나중. **그 전에 웹 디자인을 데스크톱 디자인으로 통일**(보드 화면 색 등) |
| 노출 | 라이브러리를 **일반 사용자 기본 탭**으로. **엔진 탭은 없애고 보드의 «로그» 칸으로 완전 이식** |
| 이름 바꾸기 | 폴더 소스는 **파일 이름도 같이 바꾸는 것이 기본**. 쓸 수 없는 문자 거르기 · Windows 에서 엔진이 쥔 파일의 잠금 처리 |

## 1. 출발점이 되는 사실

- 엔진은 DB 를 **한 번에 하나** 붙인다 — 웹은 메모리 FS 의 `rapfi.db`, 데스크톱 네이티브는 엔진이 연 경로(`dbStore.ts`).
  라이브러리 = 파일 여럿 + «붙은 DB» 하나(음악 앱의 «지금 재생 중»).
- 형식이 단순하다: `[LZ4 프레임] u32 레코드 수 · (u16 키 길이 · 키 · u16 값 길이 · 값)×N`, 키 = rule · w · h · 돌들, 첫
  레코드는 w = h = 0 메타데이터(`bench/dbio/yxdb.mjs`). → 병합 · 분리는 **엔진 없이 JS 워커**에서 한다(분석을 멈추지 않는다).
- 키는 엔진이 대칭 정규화한 것이고, 부모(마지막 둔 쪽 돌 하나를 뺀 국면)를 찾는 법 · 엔진과 같은 정규화는 RYDB PoC
  (`bench/dbio/rydb-poc.mjs`, §10)가 이미 검증했다. 표본의 94.2% 는 부모가 DB 에 있다.
- 엔진에 `YXSETDATABASE`(경로 바꾸기)가 있고, db4 는 저장소를 바꾸기 전 진행 중인 저장을 기다린다. db1 저장은
  `<db>.tmp` → 백업 #1(하드 링크 → 복사 → 이동) → 바꿔 끼우기, db6 저널은 `<db>.journal`.
- 26주형 분류 · 대표 세 수 · 이름(`opening26.ts`), 램프 생성 `ramp(hue, chroma)`(`ramps.ts`).
- 데스크톱만 다른 디자인(2026-11-22 확인): 보드 화면 나무 팔레트 채도 절반(`DESKTOP_WOOD_CHROMA`, `DesktopWood*`) ·
  보드 무대 절반(`--stage-a/b`), 보드 옆 칸 = 인스펙터 [개요 | 로그](`Inspector.tsx`), 펼친 레일 · 밀도.
  → **U1(같은 날) 뒤**: 나무 채도 절반은 `scheme.ts` 의 `WOOD_CHROMA` 하나(웹 · 데스크톱 공통), 무대 세기는 `base.css`
  기본값, 인스펙터는 넓은 보드 모두(웹 · 좁은 데스크톱 창 포함). 데스크톱에만 남은 것은 펼친 레일 · 밀도 · 판 밑 독
  (상태 캡슐)이다. 휴대폰 세로 시트는 아직 카드뿐 — 로그 세그먼트는 U2.

## 2. 단계

| 단계 | 내용 | 확인 |
|---|---|---|
| **U1** ✅ | 디자인 통일 — 웹이 데스크톱 보드 팔레트 · 무대를 따른다. 넓은 웹의 보드 옆 칸도 [개요 \| 로그] 세그먼트로 | 대비 시험, 스크린샷 골든 재기록(CI) |
| **U2** | 엔진 탭 제거 — 상태 카드 · 기동/끄기 · 콘솔을 보드 «로그» 칸으로. `/engine` → 보드 로그로 넘김, 명령 팔레트 · 단축키 번호 정리 | 스모크 · 골든 |
| **L0** | `core/database/yxdbfile.ts` 스트리밍 코덱 + `library.worker.ts`(통계 · 색인) | 엔진이 쓴 파일과 레코드 대조, 79MB 표본 메모리 · 시간 |
| **L1** | Dexie v6 · `LibrarySource`(브라우저) · `rapfi.db` 이관 · `dbStore.switchTo(id)` | 단위 · 이관 시험 |
| **L2** | 라이브러리 탭(기본 5탭에) · 격자 · 상세 · 이름 · `DbCover` · 커버 시트 · 열람 동선 | 대비(26주형 × 테마), 골든 `library-*` |
| **L3** | 병합 · 분리 흐름 | 왕복(나눈 것을 다시 합치면 원본과 같다) · 취소 · 강제 종료 시험 |
| **L4** | 폴더 소스 — 웹 Chromium(File System Access) · 데스크톱(Tauri, Rust 명령은 Zenyth-desktop) | Rust 는 CI 에서만 빌드(로컬 확인 불가) |
| **L5** | 안드로이드 이식 — 같은 사이드카 · 같은 색 표, SAF 트리 권한 | 앱 저장소 |

## 3. 데이터 구조

### 소스

```
LibrarySource { list · open(스트림) · writeAtomic · rename · trash · readManifest · writeManifest }
 ├ BrowserSource      모든 브라우저 · Dexie (기본. 지금의 rapfi.db 가 첫 항목 «내 DB»로)
 ├ FsaFolderSource    웹 Chromium · showDirectoryPicker, 핸들은 IndexedDB 에. 재방문 시 «폴더 다시 허용» 칩(사용자 제스처)
 └ TauriFolderSource  데스크톱 · Rust 명령. 네이티브 엔진은 YXSETDATABASE <경로> 로 파일을 직접 연다(복사 없음)
```

Firefox · Safari 는 폴더 칩을 숨기고 브라우저 라이브러리 + 가져오기 · 내보내기만.

### 메타데이터 — 폴더에 사이드카

폴더 소스는 `zenyth-library.json`(폴더를 옮기거나 안드로이드에서 열어도 이름 · 커버가 따라간다), 브라우저 소스는 같은
모양을 Dexie 에. **DB 파일 안에는 넣지 않는다**(엔진이 다시 쓰며 잃고, Yixin Board 호환을 해친다).

```ts
interface LibraryEntry {
  id: string; // UUID — 파일 이름이 바뀌어도 그대로
  file: string; // 폴더 기준 상대 이름
  title: string;
  cover: { mode: "auto" | "eclipse" | "opening"; opening?: number; seed: number };
  fingerprint: { size: number; mtime: number; tail: string }; // 크기 + 끝 4KB 해시(db6 저널과 같은 방식)
  stats?: DbStats; // fingerprint 가 같으면 다시 세지 않는다
  createdAt: number;
  updatedAt: number;
  lastOpenedAt?: number;
}
interface DbStats {
  records: number;
  rules: Record<string, number>; // "renju-15" 따위 — 섞였는지
  labels: { W: number; L: number; D: number; other: number };
  commented: number;
  openings?: number[]; // 길이 27 = 26주형 + 미분류. 메모리 관문에 걸리면 없다
  roots?: { key: string; subtree: number }[]; // 부모 없는 국면 상위 N — 열람 동선
}
```

- 앱 밖에서 이름이 바뀌면 fingerprint 로 다시 짝짓는다. 짝 잃은 메타데이터는 30일 뒤 정리.
- **쉬는 파일 불변식**: 붙어 있지 않은 파일은 늘 저널이 접힌 한 벌. 다른 DB 로 바꿀 때 `save(compact)` 를 먼저 한다 —
  병합 · 분리 · Yixin Board · 데스크톱 엔진이 모두 파일 하나만 본다.
- Dexie v6: `librarySources`(종류 · 핸들 · 경로), `libraryMeta`. 브라우저 소스 파일은 `dbfiles` 의 `lib/<id>`(+ `.journal`),
  **Blob 으로**(디스크 쪽에 두어 힙에 통째 올리지 않는다). 붙은 항목은 `rapfi.db.active`. 엔진 쪽 이름은 `rapfi.db` 그대로.

## 4. 메모리 · 백그라운드 (조건 ①)

**원칙: 풀린 바이트(표본 700MB)를 한 번도 통째로 들지 않는다.**

- **스트리밍 해제** — LZ4 프레임을 블록(≤ 4MB) 단위로 풀고, 연결 블록이면 64KB 창만 남긴다. 레코드 파서는 그 위의 링
  버퍼. 통계의 개수 세기는 O(1) 메모리.
- **색인(주형 · 뿌리)** — 레코드당 고정 폭 배열만: 키 해시 64비트(독립 32비트 둘, 비선형 — §10 의 xorshift 교훈) + 레코드
  번호 + 부모 번호 둘 + 주형 1B ≈ **레코드당 21B**(800만 → 약 170MB). 키 바이트는 두지 않는다.
  1. 1차 통과: 해시 · 돌 수 · 라벨 집계. 해시를 기수 정렬(제자리).
  2. 2차 통과: 레코드마다 부모 후보(마지막 둔 쪽 돌 하나씩 빼고 정규화)를 색인에서 찾아 **서로 다른 주형의 부모 둘까지** 적는다.
     3돌 국면은 `opening26.classify` 로 바로.
  3. 메모리에서 부모 포인터를 따라 주형을 정한다(경로 압축, O(N)). 부분 트리 크기도 같은 길에서.
- **메모리 관문** — 머리의 레코드 수로 필요량을 먼저 계산하고, `navigator.deviceMemory` 와 견줘 넘으면 색인을 건너뛴다
  (기본 통계만, 상세에 «주형 통계는 이 기기에서 생략» 한 줄). 수치는 L0 벤치로 정한다.
- **병합** — 입력이 키 순서면 k-way 스트리밍 병합(입력당 블록 하나). 순서가 아니면 정렬된 묶음을 **OPFS 임시 파일**에
  흘려 외부 병합. 출력도 OPFS 임시 파일에 스트리밍으로 쓰고(4MB 독립 블록 LZ4, JS 압축기), 끝나면 목적지로 옮긴다.
  엔진 파일이 키 순서인지는 L0 에서 확인한다.
- **매끄러움** — 작업은 전용 워커 하나(UI · 엔진 스레드와 별개). 진행 소식은 10Hz 로 묶는다. 취소는 협조 플래그
  (`SharedArrayBuffer` — 이미 교차 출처 격리) → 안 되면 `terminate()`, 임시 파일은 다음 기동에 쓸어 낸다.
- **작업 중 조작** — 작업 줄은 하나씩. 작업 중인 입력 파일은 «작업 중» 배지로 이름 바꾸기 · 지우기만 잠그고, 열람 · 붙이기 ·
  다른 탭은 그대로 된다.

## 5. 26주형 분류 (조건 ②)

- 판정은 **부모 사슬만**: 3돌 뿌리까지 이어지면 그 주형. 부모가 없거나, 부모들이 서로 다른 주형이면 **미분류**.
  돌 부분집합 매칭 같은 추측은 하지 않는다.
- 렌주 · 표준(15×15, 천원 개시)에서만 분류한다. 자유룰 · 다른 판 크기는 분류를 건너뛰고 뿌리 목록으로 보여 준다.

### 상세 · 열람 동선 (조건 ③)

물든 머리(큰 커버 · 이름 눌러 바꾸기) · 칩(규칙 · 판 · 국면 수 · 마지막 저장) · 채운 단추 하나 [이 DB 열기] · 그 아래:

| 섹션 | 언제 | 누르면 |
|---|---|---|
| 주형 분포(미니 판 26칸 + 막대) | 분류가 된 DB | 그 주형 대표 국면을 DB 붙은 판에서 |
| **뿌리 국면**(부분 트리 큰 순 상위 N) | 늘(색인이 있으면) — 자유룰 · 미분류 위주 DB 의 주 동선 | 그 국면을 판에서 |
| **[빈 판에서 열기] [편집기로]** | **늘** — 색인이 없어도(메모리 관문) | 붙이고 빈 판 / `/library/edit` |
| 기록(W · L · D · 주석 수) | 늘 | — |

미분류가 대부분이면 주형 분포를 접고 뿌리 국면을 위로 올린다. 어떤 DB 든 상세에서 판까지 한 번에 간다.

### 커버

SVG `DbCover`(이미지 저장 없음 — 주형 번호 · seed 만). 정사각, 모서리 20.

- 배경: 주형 색의 컨테이너 톤 그라데이션(라이트 90 → 80, 다크 30 → 20).
- 가운데: 천원 ±2 의 5×5 를 크게 잘라 대표 세 수. 흑 = 그 색 톤 10, 백 = 진주 `#F6F1E9`.
- **直 13 = 정방 격자, 間 13 = 45° 돌린 마름모 격자** — 간접의 대각 둘째 수가 세로로 선다.
- 색: **月(16) = 청록 ~ 보라(180° ~ 330°, 밤하늘), 星(10) = 산호 ~ 금빛(20° ~ 110°, 별빛)**. 26 색상각은 표 하나로 고정,
  시험: 모든 주형 × 라이트/다크/검은 배경 AA · 이웃 주형 OKLab 거리 하한 · `primary` · 의미색과의 거리.
- 상태 셋: **기본**(«일식» — 두 원반, `seed` 로 보라 · Mist 계열) / **자동**(가장 많은 주형) / **주형**(고른 것).
- 상세 화면은 커버 색으로 물든다(`--cov-*`, 그 화면에만 — `[data-wood]` 선례). 다른 화면은 보라 그대로.
- 커버 시트: 실시간 미리 보기 · [자동] [일식] · 直 13 / 間 13 미니 커버 격자 · 체크 원.

### 이름 바꾸기 (결정 4)

시트: 글 칸 + «파일 이름도 같이 바꾸기»(폴더 소스 기본 켬). 제목은 무엇이든 되고, 파일 이름은 제목에서 만든다.

- **거르기**: `< > : " / \ | ? *` · 제어 문자(0 ~ 31) → `_`, 끝의 점 · 공백 제거, 예약 이름(`CON` `PRN` `AUX` `NUL`
  `COM1`~`COM9` `LPT1`~`LPT9`, 확장자가 붙어도)은 뒤에 `_`, NFC 정규화, 255바이트 안으로 자르기, `.db` 유지, 겹치면 ` (2)`.
  거른 결과를 시트에 미리 보여 준다.
- **붙은 DB 의 이름 바꾸기**(엔진이 쥔 파일): 저장 · 접기 → 떼기(db4 가 진행 중 저장을 기다린다 — 핸들이 닫힌다) →
  본 파일 · `.journal` · 백업(`<db>` 의 번호 백업)을 함께 이동 → 새 경로로 `YXSETDATABASE` → 붙었는지 확인.
  떼지 않고 바꾸면 엔진의 다음 저장이 옛 이름을 되살린다.
- **Windows**: 다른 프로세스(백신 · 색인기 · 동기화 · Yixin Board)가 쥐면 공유 위반 → 짧은 간격으로 몇 번 다시 시도 →
  그래도 안 되면 원상(옛 경로로 다시 붙이기)으로 돌리고 «다른 프로그램이 쓰는 중» 한 줄, 제목만 바꾸고 파일 이름은 다음에
  다시 시도(`fileRenamePending`). 덮어쓰기 없는 이동(`MoveFileExW` 무 REPLACE), 대소문자만 다른 이름은 임시 이름을 거쳐 두 번.
- 웹 폴더(FSA): `handle.move()`. 그 파일에 쓰기 스트림이 열려 있으면 작업 줄이 끝날 때까지 기다린다.

## 7. 병합 · 분리

### 공통 안전 원칙

1. **원본을 건드리지 않는 것이 기본** — 결과는 늘 새 파일.
2. **원자적 쓰기** — 임시 파일에 끝까지 → 다시 읽어 레코드 수 대조 → 바꿔 끼우기.
3. **지우기 = 휴지통** — 10초 되돌리기 스낵바. 데스크톱 OS 휴지통 · 웹 폴더 `.zenyth-trash/` · 브라우저 저장소 앱 안 30일.
4. 붙은 DB 가 끼면 자동으로 저장 · 접은 뒤 진행(한 줄 알림).
5. 작업은 하나씩, 진행 · 취소(취소하면 임시 파일 정리).
6. 브라우저 소스는 처음 쓸 때 `storage.persist()`, 쓰기 전 `estimate()` 로 용량 확인.

### 병합 — 여러 개 고르고 [합치기], 3단계

| 단계 | 내용 |
|---|---|
| ① 순서 | 끌어서 순서, 맨 위가 기준. 규칙 · 판이 섞이면 경고 배지(키에 규칙이 있어 합칠 수는 있다) |
| ② 겹칠 때 | **[더 깊은 기록(권장)]** 깊이 큰 쪽 → 같으면 W/L/D 로 풀린 쪽 → 같으면 기준 · **[기준 우선]**. 주석 «이어 붙이기(같은 글은 하나로)» |
| ③ 미리 보기 | 실제로 쓰기 전에 센다: «합계 123만 · 겹침 1.2만 · 값이 다른 것 321». 이름(기본 «A + B») · 커버(기준의 것) · «원본을 휴지통으로»(기본 꺼짐) → [합치기] |

### 분리 — 상세에서 [나누기], 3단계

| 단계 | 내용 |
|---|---|
| ① 기준 | 카드마다 개수: **주형별**(26 + 미분류, 고른 주형마다 한 파일 또는 묶어 한 파일) · **이 국면 아래**(지금 판 국면을 포함, 대칭까지) · **풀린 국면만**(W/L/D) · **규칙 · 판**(섞였을 때만) |
| ② 나머지 | **[원본 그대로(권장, 복사)]** · [원본에서 빼기(옮기기)] — 옮기기는 원본을 휴지통에 자동 백업 + 확인 상자 |
| ③ 미리 보기 | 결과 파일마다 커버 · 이름(고칠 수 있다) · 개수. 주형별 결과는 커버가 그 주형으로 자동. 검산 «합계 = 원본 81만 ✓» → [나누기] |
