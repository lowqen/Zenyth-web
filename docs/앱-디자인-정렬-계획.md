## Z0. 기반

**규칙.** 판 색을 빼면 **화면 변화 0**. 골든은 Z0 의 다른 변경보다 **먼저**, 지금 코드에서 기록한다 — 그래야 판 색
변경의 diff 가 «판이 있는 장면만» 이라는 것을 보일 수 있다.

| | 작업 |
|---|---|
| ① 스크린샷 골든 | `scripts/shots.ts` — 빌드된 `dist/`(엔진 없음, `?autoboot=0`)를 `serveDist` 로 띄워 화면 9개(보드 · 연구 넷 · 정석 · DB · 엔진 · 설정) × 라이트/다크 × 넓은(1280×800)/좁은(390×844) 폭을 찍는다. 한국어 고정, 애니메이션 끔, 글꼴 로드 대기. `record` 는 `shots/actual/` 에 쓰고, `verify` 는 `shots/golden/` 과 픽셀 대조(채널당 ±2 허용 — 실행 기록 Z0) 후 다른 장면의 diff 를 남긴다. CI `screenshots.yml`: push · PR 마다 verify, 수동 실행(`mode=record`)은 찍은 그림을 아티팩트로 — 내려받아 커밋한다. **골든은 CI 러너에서만 유효**(앱 P0 과 같은 이유: 로컬 글꼴 래스터가 다르다) |
| ② 14램프 골든 | `tools/tone-dump/ToneDump.java` 의 램프 표를 앱 `Color.kt` 와 같게(`Maple` 70°/0.075 · `WoodNight` 70°/0.05 · `Violet` 298°/0.09 · `Lilac` 298°/0.035 · `Mist` 298°/0.005 · `MistVariant` 298°/0.012 추가 · 변경) → `tone-dump.yml` 을 돌려 `tokens.golden.json` 갱신(14 × 101 = 1,414값). `ramps.ts` 에 같은 램프. `ramps.test.ts` 는 그대로 «모든 램프 정확히 일치» |
| ③ 판 색 (Q2) | `scheme.ts` 의 보드 스킨을 `BoardSkin.kt` 대로: 라이트 `Maple` 76 · 70 · 40 · 30(나무 · 가장자리 · 격자 · 좌표), 다크는 `WoodNight` 70° 의 같은 톤. 판의 밝기(톤 76 · 33)는 그대로라 값 칩 · 돌 대비는 앱이 시험한 그대로다 |
| 하지 않음 | 역할 배정(Z1)과 글자 · 간격 토큰(Z2)은 화면을 바꾸므로 Z0 에서 빼 각 단계로 보낸다 |
| 검증 | 골든 기록 직후 verify 두 번 연속 녹색(장면이 흔들리지 않는지). ③ 뒤 diff 가 판이 있는 장면에서만 나는지 확인하고 재기록 |
